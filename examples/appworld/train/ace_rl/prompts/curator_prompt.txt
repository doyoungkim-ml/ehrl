You are an editor for a per-task AppWorld playbook. The playbook is a cheatsheet for solving this specific task, it should be concise, but it should have essential hints about the key characteristics of this task (e.g., high-level workflow pattern, verification steps to confirm

You are given:
- **Current Playbook**: The accumulated playbook from prior epochs for this task (at **Current Playbook** section below).
- **Reflector's Latest Insights**: Multiple insights from the most recent epoch's trajectory analyses. Each insight comes from a different rollout of the same task, and includes the outcome (SUCCESS or FAILED), reasoning, and key insight.

Follow the **Your 5-Step Task** section below **step by step** to decide how to manage the playbook BEFORE producing your output.

## Your 5-Step Task

### Step 1: Describe the current status of the Playbook as following:

1. Can you identify tips in the **Current Playbook** section? If the playbook is blank, note that it is empty.
2. How many tips are in the Current Playbook? If there are more than 10 tips, you should REMOVE tips that are less helpful for solving this task.

### Step 2: Evaluate each insight independently as following:

For each insight (Insight 1, Insight 2, ...):

First, evaluate the quality of this insight:
- Is this insight empty, missing, or not provided? If yes, skip this insight.
- Is this insight specific and actionable? Does it describe a key characteristic of this task, not just restate the outcome? If not, skip this insight.

Then, determine the category of this insight based on its outcome:
- Does this insight come from a successful trajectory (outcome = SUCCESS)? If yes, this is a **SUCCESS insight**.
- Does this insight come from a failed trajectory (outcome = FAILED)? If yes, this is a **FAILED insight**.

After evaluating all insights, summarize: Which insights passed quality filtering? Which category does each belong to? (e.g., "Insight 1: FAILED, Insight 3: SUCCESS. Insights 2 and 5 were skipped due to low quality.")

### Step 3: Compare the insights against existing tips as following:

If the playbook is empty, skip this step — there are no existing tips to compare against.

If the playbook is non-empty, read each existing tip and ask:
- Do any of the remaining insights (those that passed quality filtering in Step 2) relate to the same characteristic of this task as this tip? Which insights?
- If yes, do those insights collectively provide more helpful information for solving this task than this tip? Do they add concrete detail that this tip lacks?
- If yes, do any of those insights contradict this tip with corrected information?
- If no insights relate to this tip, this tip is unaffected.

Then ask: Are there any remaining insights that do not relate to any existing tip? Which ones? These point to potential new areas for the playbook.

### Step 4: Choose operations based on category and comparison as following:

Process each category separately. Within each category, use the corresponding guidance below.

**SUCCESS insights:**

- Is the current playbook adequate given the agent's success? If yes, no operation.
- Do any SUCCESS insights match an existing tip, and the agent's success suggests it has mastered that characteristic? Which insights, which tip? If yes, consider REMOVE to free space for more helpful tips.
- Do any SUCCESS insights reveal a key characteristic of this task that is not yet covered in the playbook and that the agent may not reliably attend to in future attempts? Which insights? If yes, consider ADD. If multiple insights point to the same characteristic, treat them as one and ADD once.
- Do any SUCCESS insights provide concrete operational detail (parameters, values, signatures) that an existing tip lacks? If yes, consider UPDATE to add that detail.
- Do any SUCCESS insights describe an alternative strategy that are less complex than an existing tip's strategy? If yes, consider UPDATE to replace the tip with the safer strategy.

**FAILED insights:**

- Do any FAILED insights describe a characteristic of this task that is not covered by any existing tip? Which insights? If yes, ADD. If multiple insights describe the same characteristic, treat them as one and ADD once.
- Do any FAILED insights relate to an existing tip that covers a related characteristic but was not sufficient to prevent this failure? Which insights, which tip? If yes, UPDATE to make it more specific or accurate.
- Is the failure already well-covered by an existing tip? If yes, no operation — the issue may be that the agent is not following existing guidance, which cannot be solved by adding more tips.
- The agent failed — REMOVE is almost never justified.

### Step 5: Verify your output:

1. If the playbook is empty, did you choose UPDATE or REMOVE? That's invalid — the only valid operations on an empty playbook are ADD or no operation.
2. If your operation is ADD, does it include only `type` and `content` with NO `tip_id`?
3. If your operation is UPDATE, does it include `type`, `tip_id`, and `content`?
4. If your operation is REMOVE, does it include only `type` and `tip_id`?
5. Is your content free of tip IDs like `[1]`? The system assigns IDs automatically.
6. Are there any literally similar or overlapping tips in the playbook? If yes, REMOVE the less helpful one.
7. Do any of your operations target the same tip or the same characteristic? If yes, merge them into one operation.
8. Do any of your proposed changes contradict an existing tip that  will remain in the playbook? If yes, either resolve the  contradiction by updating both tips, or remove the contradicted tip. The playbook must never contain tips that give opposing advice.
